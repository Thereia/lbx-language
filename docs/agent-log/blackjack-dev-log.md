- 记录原则：每一步先写"想做什么"，再贴关键代码，然后重点记录**报错原文 + 怎么改**，最后一步是自检结果。

## 条目 1 —— 选题与环境确认（2026-10-13）

### 想做什么

三个候选题目（21 点 / 文字版扫雷 / 文字迷宫）里选一个，并先把"要跑起来需要哪些 LBX 不具备的能力"列清楚（指南 §2.8a 的原话是「写程序前先把'我需要的能力里哪些 LBX 没有'列出来」）。

### 选题理由：选 21 点（Blackjack）

| 候选 | LBX 适配度 | 结论 |
|---|---|---|
| 21 点 | 只需要数组 + 结构 + 整数运算；一局结束条件天然清晰（破产 / 打满局数）；玩家每步是"要牌/停牌"这种**单字符指令**，不需要解析任意数字串 | **选它** |
| 文字扫雷 | 递归展开空区要递归（上限 1000 够用），但"翻格子坐标"要玩家输入两位数坐标，而 LBX **没有字符串下标、没有子串、没有 try/catch**，坐标解析只能靠穷举白名单，很别扭；而且要在记录里复现"通关"的一整局输入，得先反推雷区 | 放弃 |
| 文字迷宫 | 类似，且物品/遭遇的文本量会挤占真正有信息量的代码 | 放弃 |

关键适配点：21 点的"要牌/停牌"是**有限指令集**，可以完全用字符串相等比较处理，绕开"输入校验"这个 LBX 的硬伤（见条目 4）。

### LBX 没有、必须自己实现的能力（先列清单）

| 需要 | 归属 | 方案 |
|---|---|---|
| 随机数 | §2.8a 表里点名的第一项 | 指南 §5 的 LCG 惯用法（`seed = (seed * 1103515245 + 12345) % 2147483648`） |
| 洗牌 | 无库 | Fisher–Yates，用上面的 `randRange` |
| `max` / `min` / `abs` | §2.8a 表 | 各写三行函数 |
| 手牌算点（A 当 11 还是 1） | 无库 | 全按 11 累加 + 记 A 的张数，超 21 就每张 A 减 10 |
| 输入合法性校验 | **清单外的新发现** | 见条目 4，这是本题最大的坑 |
| 时间 / 日期（"每次不同"的种子） | §2.8a 明说没有 | 用固定种子常量，并在开场说明里告知玩家"牌局可复现" |

### 顺手撞到的第一个坑：输入给少了会直接崩

我想验证"管道喂输入"是否可行，就故意少喂几行：

```
> "10`n20" | java -cp build lbx.Main examples\guess.lbx
请输入数字：第 1 次：10 → 偏小
请输入数字：第 2 次：20 → 偏小
请输入数字：exit=1
[stderr]
[LBX 运行时错误] 行 20: int 不支持 null
```

- **原因**：语法文档 §9 说 `input()` 读到 EOF 返回 `null`（这一点指南 §2.8 表格里也有），但 `examples/guess.lbx` / 文档 §11 的示例直接写 `int(input("请输入数字："))`，没有判空。
- **我的改法**：我自己的所有读取都过一层 `askChoice()`，`input()` 返回 `null` 就走"玩家离开"的正常收尾路径，绝不让 `null` 流进 `int()` / `len()` / 比较运算。这条在条目 4 展开。

## 条目 2 —— 骨架：LCG、牌堆、洗牌、渲染（第一次跑通）

### 想做什么

先只做"牌"这一层：52 张牌怎么建、怎么洗、怎么打印，底部临时加一段调试输出（正式流程还没写）。**先让一段能跑，再往上堆游戏逻辑**，这样后面出问题一定是新代码的问题。

### 关键代码

```lbx
// 伪随机数——直接抄指南 §5 的惯用法
seed = 20261013;

func nextRand()
    seed = (seed * 1103515245 + 12345) % 2147483648;
    return seed;
end

func randRange(n)
    return nextRand() % n;
end

// 牌堆：4 花色 × 13 点数，A 先按 11 存，算点时再降
type Card = { label = "??", value = 0 };

func newDeck()
    d = [];
    for suit in ["♠", "♥", "♦", "♣"]
        for r in range(1, 14)
            push(d, Card { label = suit + rankName(r), value = cardValue(r) });
        end
    end
    return d;
end

// Fisher–Yates：数组是引用语义，原地洗，不返回
func shuffle(a)
    i = len(a) - 1;
    while i > 0
        j = randRange(i + 1);
        t = a[i];
        a[i] = a[j];
        a[j] = t;
        i = i - 1;
    end
end
```

写的时候有几处是**刻意按指南改掉了 Python 手感**的：

- `push(d, Card { ... });` —— 不是 `d.append(...)`（指南 §3 迁移表点名）；
- `i = i - 1;` —— 不是 `i -= 1`（§2.3 明说没有复合赋值）；
- 花色数组直接写字面量 `["♠", "♥", "♦", "♣"]`，因为 **LBX 字符串不可变且没有下标**，用列表遍历比用编码算字符靠谱。

### 真跑

```
> java -cp build lbx.Main apps\blackjack.lbx
洗牌前：♠A ♠2 ... ♣Q ♣K
牌堆张数：52
洗牌后前 8 张：♦8 ♣J ♦2 ♠Q ♦10 ♥K ♣9 ♠10
第一张的值：8
exit=0
```

- 52 张、四花色齐全 → `newDeck` 的双层 `for` 写法正确；
- 洗牌后顺序确实变了 → LCG + Fisher–Yates 有效；
- 第一张 `♦8` 的 `value` 是 8，与 `cardValue` 一致。

**这一步没有报错**（唯一的坑在条目 1 已经踩过了）。第一次就把 `type Card = { label = "??", value = 0 };` 的默认值写全，是因为指南 §2.4 明确写了「默认值必填」——省掉一次 `期望表达式，实际遇到 '}'`。

## 条目 3 —— 算点：A 的软硬处理（自测抓出一个真 bug）

### 想做什么

`A` 在 21 点里可以当 11 也可以当 1。我的方案：牌堆里 A 的 `value` 一律存 11，算点时先全按 11 加，超过 21 就把一张 A 减 10（等于把 11 降成 1），循环到不超 21 或没有 A 可降。

### 关键代码

```lbx
func handTotal(hand)
    total = 0;
    aces = 0;
    for c in hand
        total = total + c.value;
        if c.value == 11
            aces = aces + 1;
        end
    end
    while total > 21 and aces > 0
        total = total - 10;
        aces = aces - 1;
    end
    return total;
end
```

### 报错（不是崩溃，是输出不对——按指南步骤 2 的标准："输出内容不对同样是 bug"）

自测输出原文：

```
=== 算点自测 ===
♠A ♥9 → 20（软 true）
♠A ♥A ♦9 → 21（软 false）      <-- 错！这张应该是软 21
♠A ♥A ♦A ♣9 → 12（软 false）
♠10 ♥K ♦2 → 22（爆牌）
♠A ♥K → 21（软 true）
```

**错误原因**：我第一版的 `handIsSoft` 是这么写的：

```lbx
// 错版
func handIsSoft(hand)
    total = 0;
    aces = 0;
    for c in hand
        total = total + c.value;
        if c.value == 11
            aces = aces + 1;
        end
    end
    return total <= 21 and aces > 0;     // 用的是"降 A 之前"的 total
end
```

`♠A ♥A ♦9` 未降前 `total = 31 > 21` → 直接返回 `false`。但这手牌的正确算法是 `A(11) + A(1) + 9 = 21`，**还有一张 A 在当 11**，所以它是软牌——我的判断条件用错了"哪一版 total"。

### 怎么改

让 `handIsSoft` 做**和 `handTotal` 一模一样的降 A 循环**，降完再看**剩下的 A 张数**（剩下的 A 才是还在当 11 用的）：

```lbx
while total > 21 and aces > 0
    total = total - 10;
    aces = aces - 1;
end
return total <= 21 and aces > 0;
```

改后输出（全部正确）：

```
♠A ♥9 → 20(软)
♠A ♥A ♦9 → 21(软)
♠A ♥A ♦A ♣9 → 12
♠10 ♥K ♦2 → 22（爆牌）
♠A ♥K → 21(软)（黑杰克）
```

顺手还改掉一处自己写的废话：第一版 `totalText` 的 `if` 两个分支返回同一句 `str(t)`，等于没写分支；现在是软牌才加 `(软)` 后缀，玩家才知道自己还有"降 A 的余量"。

### 下一步

把下注 / 要牌停牌 / 庄家策略 / 结算 / 多局串起来，先跑通一整局。

## 条目 4 —— 一局流程跑通，第一次真跑就露出两个缺陷

### 想做什么

按 `下注 → 发牌 → 玩家回合 → 庄家回合 → 结算 → 下一局` 串起一局。庄家策略用最经典的那条：**补到 17 点或以上就停**（`while handTotal(hand) < 17`）。

### 关键代码

```lbx
func playerTurn(hand)
    while true
        t = handTotal(hand);
        if t > 21
            return "bust";
        end
        if t == 21
            return "stand";
        end
        a = askChoice("要牌 [h] / 停牌 [s] > ", actionKeys);
        if a == null
            return "quit";            // EOF：不能把 null 传下去
        end
        if a == "h" or a == "H"
            drawCard(hand);
            print("你要到 ${hand[len(hand) - 1].label}：${handText(hand)} → ${totalText(hand)}");
        else
            return "stand";
        end
    end
    return "stand";
end

func dealerTurn(hand)
    print("庄家亮牌：${handText(hand)} → ${totalText(hand)}");
    while handTotal(hand) < 17
        drawCard(hand);
        print("庄家补牌 ${hand[len(hand) - 1].label} → ${totalText(hand)}");
    end
    if handTotal(hand) > 21
        print("庄家爆牌。");
    end
end
```

一开始写的版本能跑通（`"1`ns`n`n1`ns`n`nq" | java -cp build lbx.Main apps\blackjack.lbx`，退出码 0），但输出里有两处明显不对：

### 缺陷 1：第 1 局刚发牌就喊"牌靴见底"

输出原文：

```
---------- 第 1 局 / 共 8 局，下注 10 ----------
（牌靴见底，重洗一副 52 张）         <-- 开局第一局，哪来的"见底"
庄家明牌：♣K（另一张扣着）
```

**原因**：`ensureDeck()` 的判断是 `if len(deck) < 15`，而我把全局初始化写成了 `deck = [];`——空数组长度 0，第一次发牌当然"见底"。功能上没崩（它会顺手新建一副），但这句话是骗人的。

**改法**：牌靴在全局初始化段就建好洗好，`ensureDeck` 只负责"打到一半快用完时重洗"，这时提示才是真话：

```lbx
deck = newDeck();
shuffle(deck);
```

改完后第 1 局不再出现该提示，而第 8 局真的用完 52 张时它如期出现（见条目 6 的完整输出）。

### 缺陷 2：同一手牌被打印两遍

输出原文：

```
你的手牌：♦9 ♦7 → 16
你的手牌：♦9 ♦7 → 16        <-- 一模一样的两行
要牌 [h] / 停牌 [s] > 
```

**原因**：`playRound` 发完牌打印一次手牌，`playerTurn` 的 `while` 循环头又打印一次。

**改法**：分工改成"起手的手牌由 `playRound` 打，`playerTurn` 只在**要牌之后**打印更新后的手牌"，并把新拿到的牌、新手牌、新点数打在一行里：

```
你的手牌：♦9 ♦7 → 16
要牌 [h] / 停牌 [s] > h
你要到 ♦K：♦9 ♦7 ♦K → 26        <-- 爆牌也看得见
```

完整多局 + 最终结算，然后构造一串输入把一整局走完。

## 条目 5 —— 又是一个"输出不对"：开场说明把种子印错了

### 现象

多局跑通后，开场说明印的是：

```
  牌靴种子固定为 685588168，所以每局牌序可复现（LBX 没有时间和随机数）。
```

可我在脚本第 6 行明明写的是 `seed = 20261013;`。

### 原因

`seed` 是 LCG 的**可变状态**，洗牌（`shuffle` → `randRange` → `nextRand`）本身就会消耗它。而 `printBanner()` 是在全局初始化（建牌 + 洗牌）**之后**、第一局开始前才调用的，此时 `seed` 已经被 52 张牌的洗牌推到了 685588168。我在说明里承诺"种子固定为 X"，印出来的却是"洗完之后的状态"。

### 改法

把"复现用的常量"和"可变状态"分开：

```lbx
baseSeed = 20261013;
seed = baseSeed;
```

说明里印 `baseSeed`：

```lbx
print("  牌靴种子固定为 ${baseSeed}，所以每局牌序可复现（LBX 没有时间和随机数）。");
```

改后印 20261013。注意：**牌序没有变**（初始 seed 仍是 20261013，洗牌消耗的随机序列一模一样），所以条目 4 拿到的输出依然能原样复现——这一点我是重跑确认过的，不是推理。

### 稳健性：输入断在半路也不会崩（对比条目 1 的崩溃）

```text
> "1`nh" | java -cp build lbx.Main apps\blackjack.lbx      # 只给"下注10 + 要牌"，然后 EOF
...
本局结果：庄家黑杰克，盈亏 -10，剩余筹码 90
```

另外两个边界也真跑过，退出码都是 0：完全不给输入（`"" | java ...` → 0 局、正常收摊）、只给垃圾输入（`"xx`nyy`nzz" | java ...` → 连续提示后收摊）。**这就是条目 1 那个 `int 不支持 null` 崩溃的正面解法**：所有读取都过 `askChoice`，`null` 只用来表示"玩家离开"。

### 为什么没有 try/catch 也没关系

指南 §3 迁移表明确写了「`try/except` —— 没有异常处理语法；用条件判断提前规避」，§2.8a 也点了"没有标准库"。所以我把"可能出错的地方"全部前置成条件判断：

1. 输入只走白名单比较（`s == "1"`、`s == "h"`），**绝不**对玩家输入直接 `int()`；
2. `int()` 只在确定是数字的地方出现（`print` 里的插值、`str(r)` 反向使用）；
3. `pop(deck)` 之前先过 `ensureDeck()` 保证牌靴非空，避免"对空数组做 pop"。

### 五、指南够不够用：够用，但有 3 处缺口

**缺口 1（最要紧）：没有"输入校验"的惯用法，示例本身还是反例。**
§2.8 只写了"读到文件结尾返回 null"，§3 迁移表只写了"没有 try/except，用条件判断提前规避"，但**没有一条惯用法告诉你怎么写**。后果是：`int(input())` 在任何一次 EOF 或非数字输入时都会让整个程序以退出码 1 死掉（条目 1 的报错原文）。`examples/guess.lbx` 和语法文档 §11 的示例都直接写 `int(input("请输入数字："))`，照抄就会踩。我建议 §5 补一段"安全读入模板"：

```
func askChoice(prompt, allowed)   // 白名单比较，null = 玩家离开，乱输只提示不崩
```

**缺口 2：字符串能力缺口散落在两节里，选型时容易漏。**
"没有 `s[0]`"藏在 §2.3 运算符表的脚注里，而 §2.8a 的"库里没有的东西"表**没有"字符串切片/查找/大小写"这一行**。我为了确认"到底能不能取字符"翻了 §2.3、§2.7、§2.8、§2.8a 四节。建议 §2.8a 表里补一行：字符串 → 只有 `len()` 和 `+` 拼接，**没有下标、没有 substr、没有大小写转换**。

**缺口 3：§8 讲清楚了规则，但没讲"怎么打印人话"。**
§8/§2.7 说明了插值里数组按 repr 打印（带引号），我照做后菜单提示变成了 `看不懂"wtf"，请输入 ["1", "2", "3", "a", "A"] 之一。`——规则没错，观感很差。缺的是"要打印给玩家看的选项，就自己拼字符串，别直接插数组"这条实践建议（我最后就改成了写死的菜单文案 + 单独的行为提示）。

**靠指南才写对的几处**（不是我自己想出来的）：

- §5 的 **LCG 惯用法**：`nextRand`/`randRange` 基本原样抄，第一次跑就把 52 张牌洗开了；
- §5 的 **`abs`/`max`/`min` 模板**：`signed()` 用 `abs`，`bestChips`/`lowChips` 用 `max`/`min`（§2.8a 说这三个都得自己写）；
- §2.8a 的 **"写程序前先把'我需要的能力里哪些 LBX 没有'列出来"**：正是照这句话列完清单后，我才判定扫雷/迷宫的坐标解析在 LBX 里代价太高，改成 21 点；
- §2.4 的 **"默认值必填"**：`type Card = { label = "??", value = 0 };` 一次写全，没在 `type` 上浪费一次报错；
- §8 的**输出规则**：决定了"手牌用 `label` 字符串自己拼，而不是直接 `print(结构)`"，玩家看到的是 `♦9 ♦7 → 16` 而不是 `Card { label = "♦9", value = 9 }`；
- §3 的 **Python 习惯迁移表**：`+=`、`.append`、`#`、`f""`、`type(x)` 这几个坑我是先看到表、探针只是去确认"报错长什么样"（第 3～7 条）。
