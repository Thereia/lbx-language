# LBX 应用开发记录（编程 Agent 写的小游戏）

> 交付物对应：作业提交内容第 6 项「编程Agent使用 ZS 语言开发的应用程序源代码，编程Agent生成的开发记录」。
> 本文是**过程记录**；Agent 自己写的一手日志在 `docs/agent-log/blackjack-dev-log.md`（645 行、7 个条目）；
> 应用源码在 `samples/app/blackjack.lbx`（462 行，有效代码 390 行）。

## 1. 这次真正要验证什么

作业的评分意图很清楚：**30 分买的不是"一个游戏"，而是"你的语言加上你的文档，能让编程 Agent 独立写出代码"**。
所以我们没有直接把应用写出来，而是把它当成一次**对开发指南的考试**：

给 Agent 的任务里，**唯一的语言参考资料是 `docs/03-开发指南-AI.md` 这一份文档**，
不给任何额外提示、不预先告诉它任何语法或坑。它写不出来、或者写得磕磕绊绊的地方，就是指南的漏洞。

因此本文的重点不是"代码有多好"，而是：**它一次就写对了吗？它在哪儿撞墙？指南缺了什么？**

## 2. 给 Agent 的任务（要点）

原文要求它是这样几条：唯一参考资料是 `docs/03-开发指南-AI.md`，先完整读一遍；
从 21 点 / 文字版扫雷 / 文字迷宫三个候选里**自己选一个**并写清理由；
源码 ≥200 行（用 `(Get-Content 文件).Count` 统计，不许靠空行凑数）；
功能完整、能从头玩到结束；**必须真跑过**且喂输入能走完一局；
边做边往 `docs/agent-log/` 写开发记录（每步含"报了什么错、错误消息原文、怎么改的"）；
只能新建 `samples/app/` 与 `docs/agent-log/` 下的文件，不许改 `src/`、`docs/01`–`docs/03`、`src/test/resources/lbx/`。

## 3. Agent 的产出

**选题：21 点（Blackjack）。** 它给出的理由值得原样记下来，因为它**引用了指南 §2.8a 的方法**：

> LBX 只有 9 个内置函数，没有字符串下标/子串、没有 try/catch，所以"解析玩家输入的任意数字或坐标"是硬伤。
> 21 点的玩家指令全是"要牌/停牌/下注档位"这类**有限指令集**，纯靠字符串相等比较即可处理；
> 扫雷/迷宫要用两位数坐标，在 LBX 里只能穷举白名单，代价过高。
>
> （补注：这是当时的事实——M10 时语言只有 9 个内置函数、数值类型只有整数。之后 v1.3 加入了
> `float` 类型与 `float()` 函数，现在共 10 个。Agent 的判断与实现都不受影响，因为 21 点的筹码与点数都是整数。）

也就是说：它是按指南 §2.8a「写程序前先把'我需要的能力里哪些 LBX 没有'列出来」做完了能力盘点，
**据此淘汰了两个候选题目**。这正是那一节想达到的效果。

**规模与结构**：`samples/app/blackjack.lbx` 共 462 行 —— 空行 38、纯注释 34、**有效代码 390 行**；
27 个函数、2 个结构类型（`Card` / `Round`）；`func/if/while/for` 开块 83 个，`end` 83 个，配平。
函数职责分得很清楚，例如牌堆与洗牌是 `newDeck` / `shuffle` / `ensureDeck` / `drawCard`，
算点是 `handTotal` / `handIsSoft` / `isNatural`，交互是 `askChoice` / `chooseBet` / `playerTurn`，
收尾是 `settle` / `playRound` / `finalReport` / `main`。

**开发记录**：`docs/agent-log/blackjack-dev-log.md` 645 行、7 个条目，条目名依次是
「选题与环境确认 → 骨架：LCG、牌堆、洗牌、渲染 → 算点：A 的软硬处理 → 一局流程跑通 →
又是一个"输出不对"：开场说明把种子印错了 → 真跑：完整输入 + 完整输出 → 收尾自检结果」。
其中含 8 处 `[LBX ...]` 报错原文。

## 4. 独立验证（不采信 Agent 的自述）

Agent 说"完成了"不算完成，我们逐项自己跑了一遍：

**一、边界纪律。** `git status --short` 只有 `?? samples/app/` 与 `?? docs/agent-log/blackjack-dev-log.md`，
`src/`、`docs/01`–`docs/03`、`src/test/resources/lbx/` **一行未改**。

**二、行数。** 亲自统计：总行数 462、空行 38、纯注释行 34、有效代码行 390 —— 满足 ≥200 行，且不是空行凑数。

**三、编译与整局运行。** `mvn -o -q compile` 退出码 0；
用 Agent 记录的输入序列（每局 `1` 选 10 筹码档、`s` 停牌、一个空行继续，最后 `q` 收工）跑一整局：

```
(($all -join "`n") + "`n") | java -cp target\classes lbx.Main samples\app\blackjack.lbx
  → exit=0，输出 99 行
第 1 局：下注 10，你 16 点，庄家 21 点，庄家黑杰克，盈亏 -10
第 2 局：下注 10，你 15 点，庄家 24 点，庄家爆牌，盈亏 +10
...
第 8 局：下注 10，你 9 点，庄家 24 点，庄家爆牌，盈亏 +10
评价：小赚（今天运气不错）
```

8 局全部打完，结局是"约定局数打满"。**注意这里我们自己先踩了一次坑**：第一次我漏了每局之间的空行，
结果只跑了 1 局就收摊了——说明这个程序的输入协议是严格的，而这本身是它健壮设计的另一面。

**四、确定性。** 同一输入序列跑两次，`Compare-Object` 逐行无差异 —— "固定种子可复现"是真的，不是它自己说的。

**五、稳健性（最关键的一项）。** 用 `< NUL` 给**真 0 字节**的输入，以及只喂垃圾输入 `xx/yy/zz`：
两种情况都 **exit=0 并正常出结算与评价**，没有崩溃。

**六、回归。** 跑解释器自己的黑盒测试集：

```
java -cp target\classes lbx.TestRunner
[tests] 共 55 个用例，55 通过，0 失败
```

55 个用例仍全绿，说明它确实没碰解释器，也说明解释器在承载一个 462 行的真实程序之后没有被"用坏"。

## 5. Agent 踩到的语言坑（含报错原文）

这一节是本文最有价值的部分：每一条都是"想按以前的语言习惯写 → 被 LBX 挡住 → 改写法"。

**其一，`int(input(...))` 在输入不足时崩溃。**

```
[LBX 运行时错误] 行 20: int 不支持 null
```

它的改法是写了一个白名单校验函数 `askChoice(prompt, allowed)`，把所有输入都过一遍。
我们额外核实了一个细节：**"空行"与"输入结束"是两件事** —— 空行读到的是 `""`，
报的是 `无法把字符串 "" 转成整数`；真 0 字节输入读到的是 `null`，报的是 `int 不支持 null`。
两条错误消息不同，处理方式也就不同（前者是玩家按了回车，后者是玩家离开了）。

**其二，按字符解析字符串。**

```
[LBX 运行时错误] 行 2: 下标运算只能用于数组，实际是 string
```

它想写 `s[0]` 来校验玩家输入的是不是数字，改成"字符串只有 `len()` 和 `+`"，于是下注改成四档白名单。

**其三，`i += 1;`。**

```
[LBX 语法错误] 行 2, 列 4: 期望表达式，实际遇到 '='
```

改成 `i = i + 1;`。

**其四，`print(type(x))`。**

```
[LBX 语法错误] 行 2, 列 7: 期望表达式，实际遇到 'type'
```

`type` 是声明结构类型的关键字，取类型名的函数叫 `typeof`。
它的备注很准确：`type(x)` **连运行时都到不了**，直接卡在语法阶段。

**其五，`if len(a)`。**

```
[LBX 运行时错误] 行 2: 条件必须是布尔值，实际是 int
```

改成 `if len(a) > 0`。

**其六，以为函数里写的变量是全局的。**

```
[LBX 运行时错误] 行 5: 未定义的变量 d
```

它在函数 A 里写了 `d = []`，然后想在函数 B 里用 `d`。
按语法文档 §7.3，赋值时作用域链里查不到就在**当前（最内层）作用域**新建，
所以那个 `d` 是 A 的局部变量。改成在**顶层**先赋值一次即成为全局。
我们复现过两种写法：顶层先赋值的那种，函数 A 里 `push(d, 1)` 之后函数 B 读到长度 1，正常工作。

**其七，`"n=" + 5`。**

```
[LBX 运行时错误] 行 1: 运算符 + 不支持 string 和 int
```

改成 `str(5)` 或 `"${5}"`。

## 6. Agent 自己抓出的 3 个逻辑 bug

这三条不是语言坑，是它按指南步骤 2 的标准——**"没有报错"不算通过，输出内容不对同样是 bug"**——
自己抓出来的，值得记下来：

1. **软 21 点误判**：`handIsSoft` 原本拿"降 A 之前"的总数判断，`♠A ♥A ♦9` 被判成非软（应为软 21）。
   改成看降完之后还剩几张 A。
2. **牌靴初值**：`deck = []` 导致第 1 局刚开始就喊"牌靴见底"。
3. **种子印错**：开场说明里印的种子是洗牌**之后**的状态值（685588168）而不是设定的种子（20261013），
   加了一个 `baseSeed` 常量解决。

## 7. 指南缺口的修补（commit `0b74221`）

Agent 报回 3 处缺口，逐条已修补：

**缺口一（最要紧）：指南没有"输入校验"惯用法，而指南所指的示例本身就是反例。**
`input()` 读到输入结束返回 `null`，所以 `int(input(...))` 会崩；可
`samples/examples/guess.lbx` 与语法文档 §11 恰恰都是这么写的，**照抄在输入不足时必崩**——它真的撞到了。

修补：`docs/03` 新增 **§5.1 安全读入**，给出 `askChoice(prompt, allowed)` 白名单模板，
写明三条要点（候选答案写成数组常量、只做字符串相等比较、调用方只判 `null` 不再转换）；
同时给 `docs/01` §11 补了一条健壮性注记，并把语法文档升到 **v1.2**（第 13 节第 11 条记录原因，
不改语言语义）。

**缺口二：字符串能力缺口散落在两节。**
"没有 `s[0]`"藏在 §2.3 的脚注里，而 §2.8a 的能力缺口表**没有"字符串切片/查找/大小写"这一行**，
它翻了 4 节才确认。

修补：`docs/03` §2.8a 补一行，写清"字符串只有 `len()` 与 `+`；要逐字符处理，
就在生成字符串时用数组把字符存下来，而不是反过来拆字符串"。

**缺口三：§8 讲了打印规则，没讲"怎么打印人话"。**
插值里放数组会输出带引号的 repr，它的提示语一度变成
`请输入 ["1", "2", "3", "a", "A"] 之一`——规则没错，观感很差。

修补：`docs/03` §2.7 补一段"给人看的提示语要自己拼"，附可复制片段。

## 8. 结论：指南够不够用

**一轮通过，没有出现"必须先改指南才能写下去"的阻塞**：Agent 读完指南直接产出了 462 行、
能跑满一局、真 EOF 下也不崩的程序，并且没有碰解释器一行代码。

但缺口一是**真实的缺陷，而且性质不好**：指南指到的示例本身是反例。这说明
"示例性代码的健壮性"也是指南质量的一部分——读者（人或 Agent）会照着最短的示例抄。
这条教训值得写进验收讲解：**文档里最短的那个例子，等于你给别人设定的默认写法。**

它明确说"靠指南才写对"的地方有 5 处，正好是 §5 的 LCG 惯用法（基本原样抄，
一次洗开 52 张牌）、§5 的 `abs/max/min` 模板、§2.8a 的"先列清单"（据此淘汰两个候选题目）、
§2.4 的"默认值必填"（`type Card` 一次写全）、§8 的输出规则（手牌自己拼 `label`，
而不是直接 `print(结构)`）。这些就是指南创造的直接价值。

**如果再让 Agent 写一个同类应用**，按现在的指南预计不会再撞缺口一、二、三，
剩下的硬边界只有字符串处理能力（已在 §2.8a 写清）与没有异常处理（已在 §3 写清）。
