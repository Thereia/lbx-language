# 导读：这个仓库从哪看起

这是一份课程大作业。仓库里的东西分成四类：**语言规格**（这门语言是什么）、**解释器源码**（
怎么实现的）、**验证材料**（测试集与性能测试）、**给你的文档**（怎么用、怎么讲）。
本文件告诉你按什么顺序看，以及每一步看完应该能做到什么。

如果你只记一句话：**验收要讲的是"实现"，所以最重要的两份东西是 `docs/07-实现讲解.md`
和 `src/main/java/lbx/` 里的三个文件——`Lexer.java`、`Parser.java`、`Interp.java`。**

## 一、先花 5 分钟认识这门语言

语言长这样（`examples/features.lbx` 的节选）：

```lbx
type Point = { x = 0, y = 0 };      // 结构类型，字段带默认值

func fib(n)
    if n < 2
        return n;
    end
    return fib(n - 1) + fib(n - 2);
end

p = Point { x = 3 };                // y 自动取默认值 0
nums = [1, 2, 3];
total = 0;
for n in nums
    total = total + n;
end
print("total = ${total}, p.y = ${p.y}, fib(10) = ${fib(10)}");
```

三条命令认识它（在仓库根目录执行）：

```
mvn -o -q compile
java -cp target\classes lbx.Main examples/features.lbx
java -cp target\classes lbx.Main examples/guess.lbx
```

看完这一节你应该知道：语句以 `;` 结束、块以 `end` 收尾、字符串里可以写 `${表达式}` 插值。

## 二、验收主线：怎么讲清"它是怎么实现的"

这条线大约两小时，顺序不能反——先建立心智模型，再读代码，最后做改动。

### 第一步（10 分钟）：看一条数据怎么走

解释器只做三件事：**字符流 → 记号流 → 语法树 → 结果**。用同一个脚本把前两步打出来看：

```
java -cp target\classes lbx.Main --tokens examples/demo-tokens.lbx
  1:1   IDENT    print
  1:6   OP       (
  1:7   STR      "hi"   hi
  1:11  OP       )
  1:12  OP       ;
  2:1   EOF

java -cp target\classes lbx.Main --ast examples/demo-ast.lbx
BLOCK
  IF
    BIN (==)
      VAR (x)
      INT = VInt[v=1]
    BLOCK
      EXPR
        CALL
          VAR (print)
          BIN (+)
            STR = VStr[v=a]
            CALL
              VAR (str)
              BIN (*)
                INT = VInt[v=2]
                INT = VInt[v=3]
```

看语法树的形状就能确认优先级：`+` 的右边是 `*` 的子树，说明乘法先算。这一步的作用是
**让后面读代码时有画面**——你知道代码要产出的是这个东西。

### 第二步（40 分钟）：跟着同一条数据读三个文件

不要从头到尾读文件，**跟着数据走**，每次只看一个方法：

1. 打开 `src/main/java/lbx/Lexer.java`，只看 `lex()` 这一个方法。它就是那个 `while` 循环：
   看当前字符决定走数字、标识符、字符串、注释、运算符哪条路。对照第一步打出的记号流，
   确认"这个记号是这段代码产出的"。
2. 打开 `src/main/java/lbx/Parser.java`，看两个地方：`parseProgram()` / `statement()`（语句用递归下降，
   和你写过的 `rd41.c` 是同一套做法），以及 `expr(int minPrec)` 配上面那张 `BIN` 表
   （表达式用优先级爬升，把九级优先级压成一张表 + 一个方法）。对照第一步打出的语法树。
3. 打开 `src/main/java/lbx/Interp.java`，看 `run()`（先登记函数、再逐条执行）、`exec()`（语句分发）、
   `eval()`（表达式分发）。走到这里，前面那棵树就变成结果了。

读完这三个文件，你应该能回答："`print(1 + 2 * 3);` 这一行，从文件字节到输出 `7`，
中间经过了哪些函数、每次经过了什么数据结构。"

### 第三步（30 分钟）：读 `docs/07-实现讲解.md`

这份文档是**为验收写的**：逐文件、逐方法讲"为什么需要它、它干什么、代码要点在哪"。
读的时候不要背细节，重点抓两样：

1. 每个文件开头的"为什么需要"——被问到"你为什么这么设计"时，答的就是这段；
2. §5 那两个真 bug 的现象、根因、修法——这是最有说服力的材料（说明你真跑过、真发现过问题）。

§6 那 17 条问答先别急着背，第四步做完再回来用。

### 第四步（30 分钟）：自己改两个地方

看懂的标准不是"读完了"，而是"能改"。这两个改动都只动几行：

**改动 1**：在 `src/main/java/lbx/Interp.java` 的 `registerBuiltins()` 里加一个内置函数 `max(a, b)`，
照着已有的 `len` 那条写。验证：

```
mvn -o -q compile
新建一个 tmp.lbx 写 print(max(3, 9));
java -cp target\classes lbx.Main tmp.lbx      →  应输出 9
```

**改动 2**：在 `tests/errors/` 里加一个你自己的错误用例（照现有文件的格式：
`.lbx` 源码 + `.expected` 期望错误消息）。验证：

```
java -cp target\classes lbx.TestRunner        →  用例数从 55 变成 56，仍然全绿
```

改坏了不用怕：`git checkout .` 一键还原。

### 第五步（20 分钟）：自测

回到 `docs/07-实现讲解.md` §6，那里列了 17 条"老师可能怎么问 + 该指给他看哪里"。
自己先答一遍，答不上来的记下编号——那几条就是你要补的地方。

## 三、按目录找东西

`docs/` 是文档：`01-语法规则.md` 是语言的权威规格（写代码时当手册查）；
`02-开发指南-人.md` 是给人看的入门教程，每条语法都写了设计原因；
`03-开发指南-AI.md` 是给编程 Agent 用的 Skill 文档（语法卡片 + 错误手册 + 自检清单）；
`04-性能测试报告.md` 是与 Python 的对比数据与归因；`07-实现讲解.md` 是验收用的实现讲解。

`src/main/java/lbx/` 是解释器的全部源码，10 个文件 1957 行，单包平铺。值得读的是
`Value.java`（数据类型）、`Ops.java`（运算规则）、`Lexer.java`、`Parser.java`、`Interp.java`；
`Main.java` 是入口、`LbxError.java` 是错误格式、`Token.java` 与 `Node.java` 是数据结构、
`TestRunner.java` 是黑盒测试运行器（这三个不用细读）。

`tests/` 是黑盒测试集，53 个用例，说明见 `tests/README.md`。
`bench/` 是性能测试脚本，说明见 `bench/README.md`。
`examples/` 是能直接跑的 LBX 范例。`apps/` 是编程 Agent 用 LBX 写的小游戏。

## 四、被问住的时候去哪找答案

"值怎么表示、为什么不用 Object" → `src/main/java/lbx/Value.java` 与 README 第六节；
"作用域和赋值规则" → `Interp.java` 的 `lookup()` 与 `assignName()`，一共十几行；
"`return` 怎么从深层跳出来" → `Interp.java` 的 `ReturnEx` 异常与 `callFunc()`；
"错误行列号怎么来的" → `Lexer.next()` 维护行号，存进 `Token`，由 `LbxError.format()` 输出；
"运算符优先级" → `Parser.java` 里的 `BIN` 表与 `expr(int)`；
"打印格式为什么这么定" → `docs/01-语法规则.md` §8，以及 `tests/cases/*.expected` 那些逐字节基准；
"为什么文档改过版本" → `docs/01-语法规则.md` §13 决策记录第 10 条。

## 五、当时的设计决定都记在哪

两处，都在仓库里：

1. `README.md` 第六节有一张"关键设计决定"表：值模型为什么显式、语法树为什么只有一个类、
   表达式为什么用优先级爬升、控制流为什么用异常、为什么不做配对缓冲区。
2. `docs/01-语法规则.md` §13 是"设计决策记录"：中文关键字要不要、浮点要不要、
   `var` 要不要、条件是否必须布尔、语句怎么分隔……每条都写了结论与原因。

被问"你为什么这么设计"，答案基本都在这两处，不需要临场编。
